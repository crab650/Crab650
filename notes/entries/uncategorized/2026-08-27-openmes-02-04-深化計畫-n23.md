# OpenMES 02–04 深化計畫

本計畫先深化既有模組，不建立新的 `05` 專案。

- `02.openmes-master-data-demo`：主檔、版本、員工、技能、設備與品質規格。
- `03.openmes-production-execution-demo`：工單、批次、工序、報工及狀態歷程。
- `04.openmes-material-inventory-demo`：需求、庫存、預留、領料、退料及交易追溯。

目標是把三個可獨立展示的 Demo 串成受狀態與規則控制的製造閉環：

```text
受治理的主檔
  → 工單發布與快照
  → 物料需求與齊套判定
  → 預留及領料
  → 受控開工與報工
  → 退料、差異核對與結案
```

## 執行原則

1. 依 Issue 編號順序施工；未完成前置 Issue，不提前實作相依功能。
2. `02` 只擁有 `001–099` migration、`03` 使用 `100–199`、`04` 使用 `200–299`。
3. 跨模組讀取可以直接查詢共用資料庫；寫入仍由資料表擁有者負責。
4. 不直接覆寫歷史交易；錯誤更正使用釋放、沖銷或相反交易。
5. 每條 Issue 必須包含 migration、服務層規則、UI、測試及文件中適用的部分。
6. 每完成一條 Issue，三個專案的既有測試都必須維持通過。

## 完成定義

一條 Issue 只有在下列條件全部成立時才算完成：

- 驗收條件全部通過。
- 新增正常、錯誤與邊界測試。
- 不直接破壞或重建正式 `shared-data/openmes.db`。
- Schema 與 Data Dictionary 已同步。
- README 或操作文件已補充。
- `git diff --check` 及相關專案完整測試通過。

## 第一個施工項目

從 `ISSUE-001` 開始。它會先建立預留的完整生命週期，避免後續齊套判定、開工控制及結案檢核建立在會卡住庫存的基礎上。
