# 當 AI 讓寫程式變便宜，什麼會變貴？

# 📘 經濟學思維：當 AI 讓寫程式變便宜，什麼會變貴？

**學習日期：2026-08-10**

## 一、今天學到的核心概念

今天思考了一個很有意思的經濟學問題：

> 當一件商品或服務變便宜之後，與它搭配使用的東西，需求可能因此增加。

經濟學中可以從 **互補品（Complementary Goods）** 與 **交叉價格效果（Cross-price effect）** 的角度來理解。

例如：

**咖啡價格下降**
↓
更多人購買、飲用咖啡
↓
糖的需求增加
↓
如果糖的供給沒有同步增加
↓
**糖的價格可能上升**

需要注意：

> 咖啡變便宜並不代表糖「一定」變貴，而是可能增加糖的需求；如果供給有限，才可能進一步推高價格。

---

# 二、什麼是互補品？

**互補品（Complementary Goods）** 是需要搭配使用，或一起使用會產生更大價值的商品。

常見例子：

| 商品 A      | 互補品 B                                  |
| --------- | -------------------------------------- |
| 咖啡        | 糖、牛奶                                   |
| 汽車        | 汽油                                     |
| 印表機       | 墨水匣                                    |
| 遊戲主機      | 遊戲                                     |
| 手機        | App                                    |
| ERP       | 顧問、導入服務                                |
| AI Coding | Domain Knowledge、System Design、Testing |

基本邏輯：

```text
A 變便宜
    ↓
更多人使用 A
    ↓
對 B 的需求增加
    ↓
如果 B 的供給有限
    ↓
B 的價值／價格可能提高
```

---

# 三、把這個概念套到 AI

AI 正在讓一件事情快速變便宜：

# 「寫程式」

以前開發一個功能可能需要工程師花好幾天。

現在透過 AI Coding Agent：

```text
需求
 ↓
告訴 AI
 ↓
AI 產生 Code
 ↓
測試
 ↓
修改
```

原本需要幾天的 Prototype，有些情況可能幾小時就可以完成。

因此：

> **Code 的供給正在快速增加。**

這時候就可以問一個重要問題：

> 如果「寫 Code」越來越便宜，那什麼東西會變得更有價值？

---

# 四、AI 時代可能變貴的東西

| AI 讓什麼變便宜   | 相對更有價值的能力               |
| ----------- | ----------------------- |
| 寫 Code      | 知道該寫什麼                  |
| 做 Prototype | 找到真正值得解決的問題             |
| CRUD / API  | Domain Knowledge        |
| 開發功能        | Requirement Analysis    |
| 產生大量 Code   | Testing / Verification  |
| 修改程式        | System Design           |
| 建立系統        | Integration             |
| 產生答案        | Judgment                |
| 建立產品        | Customer / Distribution |

因此可以理解成：

```text
Coding Cost ↓↓↓

Domain Knowledge ↑
Requirement Analysis ↑
System Design ↑
Testing ↑
Integration ↑
Judgment ↑
```

---

# 五、真正變貴的第一件事：Domain Knowledge

**Domain Knowledge = 領域知識**

例如 AI 可以很快寫一個 ERP 出貨系統。

但是 AI 不一定知道：

* 訂單什麼時候可以出貨？
* 庫存不足怎麼處理？
* ERP 與 MES 數量不同時相信哪一個？
* 船期修改後哪些資料要重新確認？
* 哪個部門有權退回？
* 退回之後狀態如何 Rollback？
* API 重送如何避免重複建立資料？
* 出貨完成後庫存在哪一個時間點扣除？

AI 可以幫忙寫：

```python
if inventory >= shipping_qty:
    allow_shipping()
```

但是最重要的問題其實是：

> **企業真正的 `if` 條件到底是什麼？**

這需要理解公司的實際流程。

所以 AI 越會寫 Code：

> **真正懂 ERP、MES、物流、生產、財務、會計、製造流程的人，反而可能更加重要。**

---

# 六、真正變貴的第二件事：需求定義

以前：

```text
需求
 ↓
工程師寫程式
 ↓↓↓↓↓
大量時間
 ↓
系統
```

大量成本花在 Coding。

AI 時代：

```text
需求
 ↓
AI
 ↓
Code
```

Coding 速度提高之後，瓶頸開始往前移。

真正困難的問題變成：

> **「你到底要 AI 做什麼？」**

如果需求本身錯了：

```text
錯誤需求
   ↓
強大的 AI
   ↓
快速寫出大量 Code
   ↓
快速完成一個錯誤系統
```

所以 AI 越強：

> **Requirement Analysis（需求分析）反而越重要。**

---

# 七、真正變貴的第三件事：System Design

AI 很容易幫我們建立：

* API
* CRUD
* Database Table
* Flask Route
* SQL
* Frontend
* Authentication

但真正的系統還要考慮：

```text
ERP
 │
 ├── MES
 │
 ├── WMS
 │
 ├── Accounting
 │
 ├── Shipping
 │
 └── External API
```

這時候問題就不只是：

> 「這段 Code 怎麼寫？」

而是：

> 「整個系統應該怎麼設計？」

因此 **System Design / Architecture** 的重要性會提高。

---

# 八、真正變貴的第四件事：Testing & Verification

AI 可以快速產生 10,000 行 Code。

但是新的問題出現了：

> **誰知道這 10,000 行 Code 是對的？**

因此：

```text
Code Generation ↑↑↑
       ↓
需要更多
       ↓
Testing
Verification
Code Review
Monitoring
```

未來工程師很重要的一項能力可能不是：

> 「我可以寫多少 Code。」

而是：

> **「我可以判斷 AI 寫的 Code 是否正確。」**

---

# 九、真正變貴的第五件事：找到好問題

以前最大的障礙可能是：

> 「我有一個 Idea，但是我不會寫程式。」

所以：

```text
100 個 Idea
     ↓
開發成本很高
     ↓
5 個 Prototype
```

AI 出現之後：

```text
100 個 Idea
     ↓
AI Coding
     ↓
100 個 Prototype
```

當 Prototype 大量增加：

> **Prototype 本身就沒有以前那麼稀缺。**

真正稀缺的開始變成：

> 哪一個問題值得做？

因此：

**Problem Discovery（問題發現）**

可能會成為非常重要的能力。

---

# 十、程式設計師的價值正在改變

以前：

```text
好工程師
=
程式寫得快
+
程式寫得好
```

AI 時代可能逐漸變成：

```text
好工程師
=
理解問題
+
定義需求
+
設計系統
+
指揮 AI
+
驗證結果
+
整合系統
+
上線維護
```

也就是：

> **工程師從「Code Producer」逐漸轉向「Problem Solver + System Designer」。**

---

# 十一、今天最重要的思考

AI 不一定讓所有工程能力都變得不值錢。

更精確地說：

> **AI 正在降低「產生 Code」的邊際成本。**

當 Code 越來越便宜，真正稀缺的東西會逐漸浮現：

```text
             AI
              ↓
        Coding 變便宜
              ↓
     ┌────────┼────────┐
     ↓        ↓        ↓
 Domain    System    Testing
Knowledge  Design   Verification
     ↓        ↓        ↓
     └────────┼────────┘
              ↓
          Judgment
              ↓
       解決真正的問題
```

---

# 十二、今天最值得記住的一句話

> **當「答案」變便宜，「好問題、好判斷、真實經驗」就會變貴。**

套用到軟體開發：

> **當 Code 變便宜，知道「該寫什麼、為什麼寫、怎麼判斷它是對的」就會變得更有價值。**

---

## 今日學習關鍵字

* Complementary Goods — 互補品
* Cross-price Effect — 交叉價格效果
* Domain Knowledge — 領域知識
* Requirement Analysis — 需求分析
* System Design — 系統設計
* Architecture — 系統架構
* Integration — 系統整合
* Testing — 測試
* Verification — 驗證
* Judgment — 判斷能力
* Problem Discovery — 問題發現
* AI Coding Agent — AI 程式開發代理
* Marginal Cost — 邊際成本

---

## 我的學習結論

AI 時代不應該只學習：

**「如何讓 AI 幫我寫更多 Code？」**

更應該學習：

**「如何理解真正的問題，設計正確的系統，再利用 AI 快速把它實現出來？」**

因為當寫程式越來越容易時，真正形成差異的，很可能不再只是 Coding 能力，而是：

> **領域知識 × 系統思維 × AI × 判斷能力**
