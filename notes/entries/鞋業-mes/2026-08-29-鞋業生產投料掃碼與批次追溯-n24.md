# 鞋業生產投料掃碼與批次追溯

## 1. 核心概念

倉庫的領料紀錄只能證明某批物料已經發給某張工單，不能直接證明它實際用在哪一批半成品或哪幾雙成品上。

若要進行生產追溯，現場還必須記錄：

> 哪個製程或工作站，在什麼時間，將哪一批投入物料，用於哪一個生產批次或半成品批次。

完整追溯通常包含兩個層次：

```text
倉庫領料：物料批號從倉庫發給哪張工單
生產投料：物料批號實際投入哪個製程及產出批次
```

## 2. 生產開始時應掃描什麼？

開始作業時不應只掃描物料號。物料號只能表示「這是什麼物料」，無法表示「這是哪一批物料」。

建議至少掃描或確認：

```text
工單／生產批次
＋製程／工作站
＋投入物料代碼
＋投入物料批號
```

依工廠管理要求，也可以加入：

- 作業員或班別。
- 設備或生產線。
- 儲位或備料區。
- 半成品捆號、箱號或容器號。
- 開始作業時間。

物料條碼至少應讓系統取得：

```text
material_id
lot_number
```

## 3. 建議的現場作業流程

假設工單 `WO-001` 要生產 100 雙鞋，成品生產批號為 `A001`：

```text
1. 作業員登入或刷員工卡
2. 掃描工單或生產批次 A001
3. 掃描工作站，例如裁斷站
4. 掃描準備投入的物料批號 L01
5. 系統驗證物料、批號、庫存及品質狀態
6. 確認開始生產
7. 換成物料批號 L02 時再次掃描
8. 記錄換批時間及當時完成數量
9. 完工時申報合格數、不良數及產出批號
```

## 4. 為什麼換料時必須再次掃描？

例如同一個生產批次 A001 的作業過程如下：

```text
08:00　開始使用物料批號 L01
10:30　完成 60 雙
10:31　換成物料批號 L02
12:00　完成剩餘 40 雙
```

若有記錄換料點，系統可以建立：

| 生產子批次 | 數量 | 投入物料批號 |
|---|---:|---|
| A001-01 | 60 雙 | L01 |
| A001-02 | 40 雙 | L02 |

如果只有開始作業時掃描一次，換料時沒有再次掃描，系統只能知道：

```text
A001 的 100 雙可能使用過 L01 和 L02
```

此時無法可靠地判定哪些鞋子使用 L01、哪些鞋子使用 L02。若 L01 發生品質問題，可能只能把 A001 整批 100 雙都列入調查或隔離範圍。

## 5. 三種追蹤精度

### 5.1 生產批次追蹤

只記錄整個成品批次使用過哪些物料批號：

| 成品批號 | 數量 | 使用的物料批號 |
|---|---:|---|
| A001 | 100 雙 | L01、L02 |

優點是現場操作簡單；缺點是物料異常時，整個成品批次都可能受到影響。

### 5.2 生產子批次追蹤

在換料、換批或重要製程切換時拆分產出批次：

```text
A001-01：60 雙，使用 L01
A001-02：40 雙，使用 L02
```

這是在追溯精度與現場操作成本之間較實用的做法，適合多數鞋業生產場景。

### 5.3 單雙序號追蹤

每雙鞋都有唯一序號，系統記錄每雙鞋的投入批號：

| 成品序號 | 生產批號 | 投入物料批號 |
|---|---|---|
| SHOE-0001 | A001 | L01 |
| SHOE-0061 | A001 | L02 |

追溯最精確，但掃描、標識及資料維護成本最高，通常用於高價產品、特殊客戶或法規要求的產品。

## 6. 鞋業為什麼還需要追蹤半成品？

鞋子通常經過多個製程，不是原料直接變成成品：

```text
原物料
→ 裁斷裁片
→ 針車鞋面
→ 成型
→ 包裝成品
```

因此，除了原物料批號，還可能需要建立裁片捆號、鞋面批號或成型批號。每一站記錄「投入批號 → 產出批號」，形成批次譜系：

```text
皮料批號 L01
→ 裁片捆號 CUT-001
→ 鞋面批號 UPPER-001
→ 成型批號 A001-01
→ 成品批號 FG-A001-01
```

下一站不必重新掃描原始皮料 L01，而是掃描上一站產生的 `CUT-001` 或 `UPPER-001`。系統透過批次關聯即可向前追溯到原物料。

這種投入與產出之間的關係，常稱為：

- 批次譜系（Lot Genealogy）。
- 物料追溯關係。
- 投入產出關聯。

## 7. 掃描時系統應做的驗證

掃描的目的不只是保存條碼，系統還應立即驗證：

- 是否為工單 BOM 允許使用的物料。
- 顏色、尺寸、版本和規格是否正確。
- 批號是否經過品質放行。
- 批號是否過期、凍結、不合格或待驗。
- 庫存是否已預留給這張工單。
- 帳面數量是否足夠。
- 是否符合 FIFO 或 FEFO 領用原則。
- 此製程是否允許混用多個批號。
- 客戶是否指定材料來源或批次。

若發現錯料、錯批或品質狀態不符，系統應阻止投料，或要求經過授權的主管進行例外放行。

## 8. 是否每個物料、每個製程都要掃描？

不一定。追蹤精度應依材料風險、客戶要求和現場成本決定。

建議優先掃描：

- 皮革、布料、網布等可能有色差的材料。
- 膠水、處理劑及油墨等有批號和有效期限的化學品。
- 鞋底、橡膠、EVA 等具有批次品質差異的材料。
- 客戶指定或品質風險較高的關鍵材料。
- 裁片捆、鞋面批等關鍵半成品。

一般包材或低風險輔料可依需要只記錄工單領料，不一定逐次掃描到生產批次。

## 9. 倉庫領料與生產投料的差別

| 作業 | 主要目的 | 建立的關係 | 是否扣倉庫庫存 |
|---|---|---|---|
| 預留 | 防止庫存被其他工單占用 | 庫存批號 → 工單 | 否 |
| 領料 | 記錄材料離開倉庫 | 庫存批號 → 工單 | 是 |
| 生產投料 | 記錄材料實際在哪裡使用 | 投入批號 → 製程／生產批次 | 依制度決定 |
| 製程完工 | 建立產出及追溯關係 | 投入批號 → 產出批號 | 不一定 |

領料和投料可能發生在不同時間，因此不能把兩者視為同一件事。物料領到線邊後，可能尚未使用、退回倉庫，或改供其他經授權的工單使用。

## 10. 目前 Demo 的能力與限制

目前 `04.openmes-material-inventory-demo` 的領料交易會記錄：

```text
工單 work_order_id
＋物料 material_id
＋儲位 location_id
＋物料批號 lot_number
＋領料數量 quantity
```

因此目前能回答：

> 某張工單領用了哪些物料批號及數量？

但還不能回答：

> 某個物料批號實際投入哪一製程、形成哪個半成品批號，以及最後用在哪幾雙鞋？

若要支援完整追溯，後續需要增加：

- 成品生產批號及生產子批次。
- 製程作業與工作站紀錄。
- 投料開始、停止和換批紀錄。
- 半成品批號、捆號或容器號。
- 每個產出批次的合格數、不良數和報廢數。
- 投入批號與產出批號的關聯資料。

這些功能較適合由生產執行模組負責；庫存模組則提供可用批號、預留、領退料及庫存交易。

## 11. 建議的實作順序

Demo 若要逐步擴充，可依下列順序進行：

```text
第一階段：工單領料記錄物料批號
第二階段：建立成品生產批次
第三階段：投料時掃描工單、工作站及物料批號
第四階段：換料時自動切分生產子批次
第五階段：建立半成品投入與產出批號關係
第六階段：提供正向追蹤與反向追溯查詢
```

正向追蹤是從原物料批號查詢其流向：

```text
物料批號 L01 → 半成品批號 → 成品批號 → 出貨客戶
```

反向追溯是從成品查詢其來源：

```text
成品批號 A001-01 → 半成品批號 → 使用的原物料批號及供應商
```

## 12. 核心結論

```text
只掃物料號，只能確認物料種類。
掃描物料批號，才能確認實際投入批次。
換料時再次掃描，才能建立批次使用界線。
記錄投入批號與產出批號，才能形成完整批次譜系。
沒有現場換批與產出紀錄，事後就無法精確追到哪幾雙鞋。
```

對一般鞋業量產而言，以生產子批次或半成品捆號追蹤通常比每雙序號追蹤更具可行性。
